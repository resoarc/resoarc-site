# ResoArc Backup & Migration (0.3 alpha)

kintoneの**専用管理アプリ内のレコードへ構造化ZIPを保存**し、既存の別アプリへ**追記だけ**で復元する、外部サーバー不要のブラウザーカスタマイズです。正式版ではありません。認証情報はコードやバックアップに格納しません。kintoneのログインセッション・アクセス権で操作します。

## 管理アプリの作成

kintoneで専用アプリ `ResoArc Backup` を作成し、フィールドコードを**完全一致**で設定します（フィールド名は任意）。

| フィールドコード | 種類 | 用途 |
| --- | --- | --- |
| `BackupName` | 文字列（1行） | 世代名 |
| `SourceAppId` | 数値 | バックアップ元アプリID |
| `ArchiveHash` | 文字列（1行） | ZIPのSHA-256（64桁） |
| `BackupVersion` | 文字列（1行） | 保存形式バージョン |
| `RecordCount` | 数値 | レコード数 |
| `Archive` | 添付ファイル | 構造化ZIP |

**管理アプリのアクセス権**はバックアップ・復元担当者だけに絞ってください。バックアップには業務データ・個人情報も含まれます。保存先の管理アプリが対象アプリと同じドメインであることが前提です。ゲストスペースは現在未対応。

## ビルド・設定

```bash
cd plugins/backup-migration
npm ci
npm run check
```

成果物 `dist/resoarc-backup.js` を、管理アプリの **設定 → JavaScript / CSSでカスタマイズ** にPC用JavaScriptとして登録し、アプリ設定を更新してください。複数のアプリに入れる必要はありません。PC版レコード一覧の上部に操作パネルが出ます。外部CDNやサーバーは利用しません。npm依存ライブラリのライセンスとソースは npm のロックファイルで固定します。

1. **バックアップを作成**：元アプリIDを指定し、Cursor APIでレコード取得、フォーム定義・配置・添付ファイルを集めてZIP化。SHA-256計算・アップロード後、管理アプリにバックアップレコードを作成します。
2. **復元プレビュー**：管理レコードIDと既存の復元先アプリIDを入力。ZIPハッシュ、内部ファイルのハッシュと構造、復元先のフィールド型を検査し、対象件数と除外項目を表示。
3. **復元を実行 (重複防止付き追記のみ)**：明示的な確認文字列と最終確認を要求します。既存レコードの更新、削除、アプリ設定変更は一切行いません。確認なく作成済みレコードは削除されません。

## ZIP v2（v1も読み込み可能）

- `manifest.json` : `format`, `version`, `sourceAppId`, `recordCount`, `createdAt`, 内部パスとSHA-256
- `schema/fields.json` : 転送可能フィールドのコードと型、テーブル内のフィールド
- `schema/layout.json` : 元のフォーム配置の**参照用**情報
- `schema/source-fields.json` : フィールド名・選択肢・設定など、**新規アプリ構造生成の参照情報**（v2から）
- `data/records.jsonl` : 1行1レコードのJSON、サブテーブルを含む
- `attachments/<sha256>` : 添付ファイルの原本バイト列。JSONL内の `ref` とハッシュで関連づける

ZIPの全体SHA-256は管理アプリの `ArchiveHash` に記録。アーカイブ内の各データにもSHA-256を持たせ、読み戻しで再計算します。添付ファイルは復元先ドメインへのアップロードで新しいfileKeyを発行する必要があります。

## 現在の安全上限・未対応範囲

- **非圧縮アーカイブ総量とZIP本体は25MiB以内、20,000レコード以内、ZIP内エントリ数は50,000以内**。ブラウザーの負荷軽減のため保守的に制限しています。容量超過は黙って間引かず中断します。
- ファイル・フィールド・レコードの**閲覧権限がある内容のみ**取得できます。全データの完全性を保証しません。バックアップ作成中にデータが変わった場合の完全な同時点スナップショットではありません。
- レコードの追加可能な**書き込み可能フィールドのみ**対象（数式、システムフィールド、ルックアップ値は対象外）。元レコードID、コメント、変更履歴、作成者・更新者・日時、ステータス履歴、ルックアップの参照元アプリ、プロセス管理、権限設定、一覧などは復元しません。
- 復元は**既存アプリの同じフィールドコード**へ追記します。v2バックアップからは新規アプリの**フォーム下書きを作成可能**ですが、既存アプリへのフィールド変更・本番反映・データの自動移行は行いません。v0.3ではJSON対応表による明示的なフィールドコード対応付けが可能です。型不一致なら拒否します。項目が存在しない場合はプレビューで警告して除外します。
- 復元前に必須フィールド・ドロップダウン選択肢、参照先ユーザー、テーブル制約など**移行先の入力制約が一致**することを確認してください。APIの登録時に失敗する場合があります。バッチ途中で失敗した際は一部の追加が済んでいる可能性があります。v0.3は復元先の重複禁止識別子を確認して明示的に再開できますが、**v0.1～0.2で登録した識別子なしのレコードは検知できません**。自動リトライはしません。
- 管理アプリの削除・ドメイン全体の停止・契約終了時には管理アプリ上のバックアップも使えません。管理アプリからZIPを別途ダウンロード・外部保管する運用を推奨します。
- ゲストスペース、1GB級巨大データ、完全差分バックアップ、定期スケジューリング、レコードへの上書き復元は未対応です。

## テスト

\u0060npm test\u0060 はkintone APIへの実通信を行わない、形式・整合性・サブテーブル・添付・移行計画・Cursor異常系・501件の模擬API往復試験を含みます。実環境のアクセス権、ファイル上限、通信の途中失敗などは、必ず**検証用kintoneテナント**で別途試験してください。実データへの復元は行わず、最初にプレビューをご確認ください。

## 別ドメイン・別テナントへの移行（α）

元の管理アプリの添付欄からZIPを保存し、移行先ドメインのバックアップ管理アプリの一覧画面で **外部ZIPから移行プレビュー** を選択してください。kintoneのブラウザーセッションに紐づくAPIだけで操作します。移行先の既存アプリIDを指定して構造と件数を検証し、確認後に追記します。外部ZIPは自動では管理アプリに保存されません。移行元・移行先の両方で閲覧・追加の必要な権限があること、元ZIPを信頼できる経路で入手したことを確認してください。

## v2: 新しいkintoneアプリのフォーム下書きを作る

新規バックアップはv2です。v1のZIPは従来どおり既存アプリへの追記復元に使えますが、フォーム定義が不足するため自動生成には使えません。

1. 管理アプリの一覧画面で **管理レコードから新規アプリ構造プレビュー** または **外部ZIPから新規アプリ構造プレビュー** を選ぶ。
2. 新しいアプリ名を入力し、作成可能なフィールドと除外理由を確認する。
3. **新規アプリの下書きを作成（データは書かない）** から `CREATE <アプリ名>` を正確に入力し、再確認する。
4. 作成されたアプリIDを控え、kintoneのアプリ設定画面でフォームを確認する。必要な配置・参照・権限・検証を手動で設定してから **アプリを更新** する。
5. レコードが必要なら、元の管理レコードまたは外部ZIPを使い、作成したアプリIDへ **復元プレビュー → 復元を実行** を行う。

**作成されるのは新規アプリの動作テスト環境のフォーム下書きのみ。** 元のアクセス権、一覧、表示レイアウト、アクション、プラグイン設定、プロセス設定、ルックアップ/関連レコード連携、履歴は自動再現しません。参照元ユーザー・組織といったドメイン固有情報も移しません。

データ移行しやすい状態を優先し、**必須設定・一意制約・初期値も引き継ぎません**。必要に応じて管理者が復元後に設定してください。新規アプリ作成とフォームフィールド追加には権限が必要です。APIの途中失敗では下書きアプリだけ残ることがあるため、表示されたIDから管理者が確認してください。自動削除はしません。

kintone実環境でのAPI結合試験・権限試験はまだ実施していないため、正式運用前に検証テナントで必ず試験してください。

## v0.3 フィールドコード対応付けと重複防止付き再開

移行元・移行先のフィールドコードが違う場合は、**復元プレビュー**でJSONの対応表を指定します。

```json
{
  "Title": "Name",
  "Rows": "Lines",
  "Rows.Memo": "Lines.Note"
}
```

同じフィールドコードは対応表への指定を省略できます。テーブル内項目は `元テーブル.元項目` → `移行先テーブル.移行先項目` と指定します。親テーブルも明示的に対応付けてください。異なるフィールド型への暗黙の変換や、複数項目から1項目への集約は行いません。

### 復元先アプリの事前設定（必須）

**復元先の各アプリに、重複禁止にした「文字列（1行）」フィールド `ResoArcRestoreKey` が必要です。** このフィールドコードは完全一致にしてください。復元識別子以外の用途に使用しないでください。v0.3以降の新規アプリ下書きには自動的に追加します。**既存アプリのフィールドは自動変更しないため、管理者が追加・設定反映してください。**

管理者がこのフィールドへの閲覧・登録権限を復元実行者に付与する必要があります。全レコードを閲覧できない権限だとスキャン結果は不完全になる可能性がありますが、重複禁止制約は同じキーを持つレコードの二重登録を防ぎます。権限不足や同時操作による競合はエラーで中断します。

### 再開動作

- ZIPのSHA-256とフィールド対応表から、行番号ごとの復元識別子を生成します。
- 復元前プレビューで移行先にある識別子を読み、**復元済み件数と未復元件数**を表示します。
- 復元時にも再取得し、未復元レコードのみ最大20件単位で追加します。登録済みレコードの内容を上書きしません。
- 通信が切れた直前の登録結果は不明な可能性があります。**自動リトライはしません**。同じZIP・対応表を再び指定してプレビューし、確認してから再開してください。
- 同一ZIPを別の対応表で途中から復元しようとした場合は安全のため中止します。
- **v0.1～0.2によって識別子なしで追記済みのレコードは検出できません。** そのような環境で再投入する前に重複を点検してください。

復元先の選択肢不一致、対応付けられない必須項目、フィールド型不一致も書き込み前に検出して中止します。ユーザー/組織マスタ、関係フィールド、その他のドメイン固有条件は完全検証できません。処理をまたいだ一括トランザクションや取り消し処理はありません。

**重要:** 同じ管理アプリにバックアップを保管する方式は、kintoneテナント自体の停止・消失をカバーしません。ZIPの外部保管を併用してください。kintoneでの実環境API結合試験はまだ実施していません。

### 実ブラウザを使った画面試験（メインPC専用）

メインPCでは一時的な独立Edge、Linux CIではChromeを起動し、配布JSを実際のブラウザに読み込んで、操作パネルから501件のバックアップ・復元を確認できます。通常のブラウザプロファイル・kintoneログイン情報は使用しません。

```bash
npm run test:browser
```

テスト専用のローカルHTTPページに模擬kintone APIを組み込み、ZIP生成・再読み込み、復元プレビュー、26バッチでの追記、再プレビュー0件を確認します。さらにZIP改ざん、復元先の重複禁止設定不足、不正な確認文字列を画面から再現し、いずれも書き込み前に停止することを検査します。復元先への最初の20件の登録は完了したものの通信応答だけが失われた状況も模擬し、再プレビューで残り481件を検出し、確認後の再開で重複なく501件に到達することを検証します。 新規アプリのフォーム下書き作成も画面から模擬実行し、プレビューAPIだけが呼ばれ、アプリの本番反映・既存レコード変更が発生しないことを検査します。**実テナントへのログイン・APIアクセス・データ変更は行いません。** 通常のEdgeプロファイルも変更しません。

## 認証済みkintone APIの読み取り診断

メインPCのMole Remote専用Edge（`Documents\\MoleRemote\\BrowserCDP`）に対象テナントのタブを開き、**その専用Edgeで正規ログイン済み**の場合に、以下を実行できます。

```bash
node scripts/tenant-api-probe.mjs --origin https://YOUR-TENANT.cybozu.com --app 123
```

対象アプリの `GET /k/v1/app.json` と `GET /k/v1/app/form/fields.json` だけを調べ、HTTPステータス、JSON応答かどうか、リダイレクト有無、読み取り試験の成否を表示します。API応答本文、パスワード、Cookie、CSRFトークンは保存・表示しません。401は未認証、403は権限不足の可能性があります。通常のEdgeと専用Edgeではログイン状態が共有されません。

この診断は読み取り権限しか検証しません。実バックアップ・復元試験の代わりにはなりません。
