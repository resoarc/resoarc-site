# ResoArc Clock v0.3.7：Cloudflare Cron実行の書き込みE2E検証

- 検証日：2026年10月17日（JST）
- 検証対象：kintone管理アプリID 50、検証用データアプリID 52
- 判定：**限定したCron書き込み試験は合格。正式リリース判定は保留。**

## 確認した事実

| 確認 | 結果 |
| --- | --- |
| Cloudflare再認証 | 成功 |
| Workerの稼働構成確認 | Cloudflare APIから実デプロイを取得して照合 |
| 書き込み許可版 | 2026-10-17 03:20:36 JSTに配備された版は `RA_ALLOW_WRITES=true` |
| 許可対象 | **管理バッチID 10のみ・書き込み対象アプリID 52のみ** |
| 実行完了記録 | kintoneアプリ50のバッチID 10は「正常終了」、履歴1件、一回実行後の自動停止 |
| 対象レコード | kintoneアプリ52に対応する検証データ1件が登録された。値 `Stage=CLOUD_CRON_CREATED` |
| 書き込み禁止へ復帰 | 2026-10-17 03:21:19 JSTに`RA_ALLOW_WRITES=false`版が配備されていることを確認 |
| 実行後のデータ整理 | アプリ52の検証レコードを削除。アプリ50の有効バッチ0件、アプリ52の残件0件 |
| 通常構成へ復帰 | その後さらに、E2E限定バッチ・限定アプリの設定を削除して**通常の読み取り専用Worker**へ再デプロイ |
| 最終安全確認 | `npm run cloud:preflight` が `ready=true`、`remoteReadOnlyVerified=true` |

Cloudflareの**配備履歴、検証アプリに生成されたレコードと実行完了履歴が一致**したことを以て、Cron書き込み経路の限定E2Eを合格と判定した。今回の確認ではCloudflareの生ログ本文は保存していないため、Worker内部の呼び出し時刻を秒単位まで再現する監査証跡ではない。

## セキュリティ対策

- 旧JSON実行経路からE2E制限を迂回できないようにしている。
- Cron側で任意バッチを実行する許可は出さず、当該検証ジョブに限定した。
- テストは`RA_ALLOW_UNSCOPED_WRITES=true`を使用していない。
- 実行後はCloudflareの書き込み許可を解除し、kintone検証用データはすべて清掃した。
- 一時的に作成を試みた別Workerは、事前条件に不一致があったため**配備前に中止**。残留する別Workerはない。
- テナントホスト名、APIトークン値、アカウント名、署名秘密鍵、個人のローカルパスを記載していない。

## 残る確認事項

**CloudflareのAPIトークンは閲覧専用へ復帰済み。** kintone管理アプリID 50の既存の閲覧専用トークンを識別し、実際のGETが成功することを確認後、値を出力せずにCloudflare Secret `KINTONE_API_TOKENS` に再設定した（成功結果確認済み）。検証用に追加した書き込み権限付きトークンは撤収し、アプリID 50には閲覧専用トークン1件、ID 52にはトークン0件であることを設定画面で確認した。加えてCloudflare稼働版をE2E用の設定変数がない通常の閲覧専用構成へ再デプロイし、最新デプロイの設定確認と実kintoneのテストデータ残件0件を確認した。値やアカウント識別子は記録・公開しない。

また、v1.0公開前には独立したコードレビュー、Cloudflare無料枠・サブリクエスト上限の再検証、回線遮断による結果不明時の復旧運用、二重登録の冪等性設計の確認が必要。
