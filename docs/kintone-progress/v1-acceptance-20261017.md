## 正式版にするための検証手順

1. ソース、OSSライセンス、設定保存、インストール用独立manifest、バイナリ署名と署名鍵識別を確認。
2. 専用kintoneテストアプリにインストールし、PC・モバイルで正常系・誤入力・権限不足・二重保存・大量データを試す。
3. サブテーブル・既存プラグインとの共存、ゲストスペースとAPI通信回数、認証失効、障害回復を試す。
4. 変更のない利用者データを壊さないことを確認し、作成したテストレコードだけを特定IDで削除する。
5. 全証拠をtracker.jsonに結び付けて初めてリリース承認し、GitHub配布URLとサイト遷移を確認する。

## 改修の原則

- 未検証のZIPを`v1.0`や正式版として配布しない。バージョン番号は製品ごとの互換性を守る。
- 現在のβ版ソースを回収できた場合は新実装と突合し、既存版を取り違えない。
- 公開された署名鍵、Cookie、APIトークンを保存・公開しない。
- バッチ処理の外部クロック、通知、再実行と権限に関連する条件は独立して受入。
