# ResoArc 16機能：本番相当化・受入判定表

更新日：2026-10-16

## 判定原則

**本番相当**とは「動作するソースがある」ことではなく、導入形式・自動テスト・kintone環境での受入・権限・競合・復旧・利用制限が確認できた状態を指す。未実施を完了とは記録しない。

今回、5種類の追加プラグイン設定画面は公式 `kintone.app.getFormFields()` で実際のフィールドの存在を確認して保存し、日付計算・一覧編集では入力／出力フィールド型を検査するよう強化した。フィールド定義を取得できなければ保存しない。日付計算は作成・編集の保存直前にも再計算し、不明な対象フィールドによる保存を拒否する。テスト環境での確認は引き続き必要。

2026-10-16、**読み取り専用Web診断8機能のみ v1.0.0 として正式リリース**。その他の既存2種類のWebツールは個別のバージョン管理を維持。kintoneプラグイン8機能は自動テストと導入形式を強化した評価版であり、kintone実環境の受入試験は未完了、本番承認を保留する。署名付きZIPの存在は安定版の保証ではない。

## インストール検証用パッケージ

- `/products/kintone/qa/` に8種の**署名済みQA専用ZIP**を掲載。秘密鍵はリポジトリ外に保管。
- 公式 `@kintone/cli` の `plugin pack`・`plugin info` で生成・読取し、二重ZIP内のアセットが公開ソースとバイト一致することを検証。
- 初回発行したプラグインIDは旧版とは異なる可能性がある。**既存アプリへの上書き更新ではなく新規テストアプリへ導入**すること。
- 検証アプリで権限、誤入力、モバイル、他プラグイン共存、再インストール、ブラウザ差異を試験してから本番に格上げ。

## Webツールの取扱制限

- CSV / TSV / JSON はブラウザ内だけで処理。サーバーへアップロードしない。
- 入力ファイルは12 MiB以下。レコード50,000行以下。帳票は5,000行・50列以下。
- 読取専用ツールではkintoneアプリや設定の自動更新はしない。設定・権限の分析は実環境の効力判定ではない。
- CSVの引用符、列数、重複見出し、不正JSON、件数超過、数値演算の異常を検出する。
- 複数アプリのデータを扱うときはファイルに含まれる個人情報・機密情報の取扱に注意。外部送信ゼロは対象ツール自身の処理についての記載であり、ブラウザ・拡張機能や外部環境の通信を保証しない。

## 一覧編集の安全性

- 書込機能は *専用のテストアプリ* で確認。レコードごとの逐次PUTから、最大100件を1度に送る `PUT /k/v1/records.json` に改修。
- 更新直前にGETで対象レコードの現在値・リビジョンを確認し、プレビューから変更されていればPUTを実行しない。読取権限不足、レコード欠落、値の変化も更新前に拒否。
- APIはエラー時にその一括更新を取り消す（kintone公式仕様）。更新時にリビジョンを照合し、無効なフィールド型と値はリクエスト以前に拒否。
- 更新後の自動ロールバック機能はない。通信途絶で応答不明なら再送信せずkintone画面で結果を確認。
- 既存プラグイン・独自JSとの保存イベント相互作用と利用者権限は実環境での検査が必要。

## 配布・運用手順

1. 8種のプラグイン・Webのユニット／ブラウザテストと、全16機能ゲート `scripts/verify_suite16_readiness.py` を通す。
2. 公開ファイルのハッシュを `scripts/update_manifest.py` で更新し、`scripts/verify_site.py` を実行。
3. ResoArc専用GitHubへコミット（個人の識別情報や秘密鍵は含めない）。
4. 独立した本番デプロイ検証 `scripts/deploy_canonical.ps1` に従う。公開後にダウンロードZIPのSHA-256とページの警告を再照合。
5. kintoneテスト環境で各機能の受入記録を作るまでは、安定版・本番承認とは表示しない。

## ロールバック

- Webは前の検証済みコミットを再デプロイする。公開ハッシュとファイルが一致することを確認。
- プラグインは新規QAテストアプリに限定し、問題時はアプリ上で無効化して以前の状態を確認。既存アプリへの置換を前提としない。
- 署名秘密鍵を紛失すると同じプラグインIDで更新できなくなるため、公開せずバックアップを管理する。
