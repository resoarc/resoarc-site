## Required review for each of the 35 assets

For every release filename and SHA-256 in the public inventory, the maintainer must record:

1. Which files are wholly original work and whether the operator can validly offer them under MIT.
2. Which files contain contributed code, upstream packages, generated sources, fonts, photographs, and/or code taken from other repos; exact upstream project, version, author and license evidence for each.
3. Whether all **released software assets** use a license accepted by the OSI or FSF, with full text and notices delivered alongside their archives. If something is outside the software-license scope, explain and isolate it, rather than treating the entire archive as unqualified MIT.
4. Whether a particular asset's source is preserved in a trusted build log, public source snapshot or an accurately labeled later extraction. For the signed set, review all **10 Git-absent** and **4 Git-partial** assets explicitly.
5. Whether any third-party code, modified upstream copyright header, patent, trademark or distribution agreement prevents that license offer. A doubtful item must remain HOLD pending clarification.
6. Preserve supporting nonsecret evidence (source commit, original author/license document, build/QA manifest checksum, signed archive SHA-256, real review date).
