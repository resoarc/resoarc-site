SECURITY RESEARCHResoArc実務ガイド

小さな観測点を、確かな防御へ。

ResoArcが研究するTrapNetのSonar・HUB・Guardian、偽情報対策、安全な運用、技術レビューの募集について説明します。

TrapNetとは

TrapNetは、インターネット上の不審な探索・接続を観測し、複数の観測点の情報を安全に集約することを目指すResoArcの研究プロジェクトです。一般利用者向けの防御機能を含め、現在は設計・検証段階です。

スキャンらしい通信が観測されても、それだけで悪意ある攻撃者や国籍を特定できるわけではありません。研究目的のインターネットスキャナー、設定ミス、通常の通信も区別する必要があります。

三つの役割

  1. Sonar：インターネットの通信を観測し、必要な証拠を限定的に記録する観測点。
  2. HUB：観測結果を集約し、偽報告や重複、情報の鮮度を確認する中継・評価側。
  3. Guardian：配信された情報を利用者側で評価する防御機構の構想。第三者からの報告だけで重要な遮断判断を確定させない設計を目指します。

安全性を優先する原則

  • 観測点が特定・模倣される前提で考える。
  • 一つのIPアドレスや観測イベントだけで攻撃者と断定しない。
  • 偽造・再送・偏った報告による誤判定を想定し、情報の信頼度を分ける。
  • 観測用環境と利用者の重要な端末を分離する。
  • 自動遮断など影響の大きい動作は、十分な検証と人によるレビューを経る。

第三者による十分な安全性審査や、配布後の防御効果を保証する段階にはありません。

研究の進捗と関連情報

背景や分散防御網の設計方針は ResoArcのTrapNet開発記事（note） にもまとめています。設計書と公開済みの内容は、実装を保証する完成品ではありません。

攻撃観測の結果は、プライバシーや誤帰属への配慮を前提に、確認済みの事実と推測を分けて扱います。脆弱性の一般情報は別プロジェクトの SWWW（脆弱性天気予報） で確認できます。

実装・設計に関する疑問や改善案は、TrapNet設計レビュー・協力募集（GitHub Issue #31） を通じて提案できます。機微な脆弱性報告は公開Issueに直接書かず、セキュリティ案内を参照してください。

公開：2026年10月28日。仕様や防御効果を保証するものではありません。関連する操作は必ず実環境と公式仕様で確認してください。
