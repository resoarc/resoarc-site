04BACKUP / RESTORE GUIDE利用者向け復元ガイド

保存するだけでは、
バックアップは完成しない。

実際に開けること、必要な範囲が入っていること、安全に再開できることを確認するための手順です。

ResoArc.

資料更新：2026年10月22日 ／ 対象：Backup & Migration v1.0.0 正式版

v1.0.0正式版の配布を開始しました。

導入前にカスタマイズJavaScript形式であること、個人情報の取扱い、制限事項を確認してください。正式版の配布ファイルとSHA-256を確認する ↗

開発・検証の履歴を確認する ↗

1. 導入と範囲カスタマイズJS形式、権限、対象 2. バックアップ取得件数、暗号化、分割、別媒体 3. オフラインで確認ファイルと添付を閲覧 4. 追記復元フィールド対応と重複防止 5. 障害時の対応二重書込みの防止と中断 6. 個人情報と制限平文、メタ情報、非対象データ

対応環境：kintoneのPC用JavaScriptカスタマイズが利用できる契約と管理権限が必要です。ライトコースおよびkintoneのスマートフォン版は非対応です。kintone公式ヘルプ ↗

01 / INSTALLATION

まず、隔離した検証アプリで導入する

正式配布を開始した後は、管理者が検証用kintoneアプリの「JavaScript / CSSカスタマイズ（PC用）」に kintone/resoarc-archive-kintone.js を登録する方式です。署名済みkintoneプラグインZIPをインストールする方式ではありません。 アプリ設定更新前に利用者の権限と取得できるフィールドの範囲を確認します。

アプリの管理権限、必要なレコードの閲覧権限がない場合、取得できるデータは限定されます。業務本番アプリで初めて試さず、合成データのテスト用アプリで手順を確認してください。

02 / EXPORT

ローカルバックアップを取得する

レコード一覧で「このアプリをローカル保存」を選択し、対象レコード数、添付、取得できなかった設定の有無を確認します。保存形式は未暗号化 .ra-kintone または暗号化 .ra-kintone.enc です。

分割出力時は全パートと最後の索引 resoarc-collection.ra-collection.json を必ずセットで保管します。索引がない、あるいはパートが欠けている場合はバックアップ成功と判定しません。

保存後は元アプリID・取得日時・件数・各ファイルのSHA-256を控え、別媒体へコピーしてください。SHA-256は破損や改変の検出に役立ちますが、作成者を保証する電子署名ではありません。

03 / OFFLINE VIEWER

ネットワークから切り離して中身を確認する

配布セットの viewer/index.html、viewer/viewer.js、viewer/viewer.css を同じフォルダーに配置し、EdgeまたはChromeで開きます。元のバックアップは上書きせず、コピーを使って検査します。

保存したファイルまたは分割索引と全パートを指定し、レコード件数・フィールド・添付の内容とハッシュを照合します。暗号化している場合は保存時のパスフレーズが必要です。パスフレーズを忘れるとResoArcでは復元できません。

04 / CONTROLLED RESTORE

別のアプリへ、まずプレビューしてから追記する

復元先に文字列1行・値の重複を禁止するフィールド ResoArcRestoreKey を作成し、アプリ設定を更新してください。復元前に元・先アプリのフィールドコード、型、必須条件、添付、件数を確認します。

アーカイブを読み込んだら、対応表と除外項目を確認し、読み取り専用の復元プレビューを実施します。想定外なら中断。復元開始の明示確認後に追記のみ実行します。既存レコードの更新・削除には使いません。

通信応答が途中で途絶えた場合、成功していないと決めつけて連続実行しないでください。復元先のレコードと復元キーを確認し、同じアーカイブ・対応表でプレビューから再開してください。

05 / FAILURE RECOVERY

エラー時は安全側に停止する

状況行うこと
ファイルや索引が欠ける / SHAが一致しない展開・書込みを中止し、安全なコピーから再取得する。
暗号化パスフレーズを失った復元を中止する。既存の別バックアップを確認する。
フィールド制約が合わない復元先の型・必須設定・対応表を見直してプレビューを再実行する。
書込み後の応答が届かない復元先の実データと重複防止キーを確認してから手動で再開する。
権限・容量・API制限処理を止め、管理者の許可を得たうえで原因を解消する。
06 / PRIVACY & LIMITS

保存するデータには個人情報が含まれます

未暗号化バックアップには氏名・取引内容・添付などが平文で入ります。暗号化した場合も分割索引のアプリID、件数、ファイル名、ハッシュなどが平文で残る場合があります。社内規程に従い暗号化媒体、アクセス制限、保存期間・削除方法を決定してください。

1ファイル25MiB、1バックアップ20,000レコード、ZIPエントリ50,000などの上限があります。分割時も1パート25MiB、最大256パート・総256MiBです。すべてのコメント、監査履歴、ユーザー、スペース、権限、カスタマイズを完全復元できるわけではありません。取得中に変更されたレコードの厳密な同一時点再現も保証しません。

バックアップファイルをResoArcのサーバーへ自動保存する設計ではありませんが、バックアップ・復元の過程では利用者が管理するkintoneとの通信が発生します。

VERIFIED SCOPE

検証した範囲と、まだ提供していないもの

単体・異常系116項目、隔離Edgeブラウザーで合成501件の動作、固定配布ZIPのオフライン検証22項目をPASS。隔離した実kintone QA環境では合成3,001件の中断・手動再開・再実行時の追加0を確認しました。

これは実施した条件での検証結果であり、すべてのテナント・全データ形式の完全性を保証するものではありません。正式公開の判断とダウンロードの提供は別途行います。

公開を待つ間も、復元計画は準備できます。

対象データの範囲、適切な保存先、復元先のフィールド対応、検証できる環境を先に決めておくと、実際の障害時の混乱を減らせます。
