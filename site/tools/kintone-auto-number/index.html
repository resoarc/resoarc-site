v1.1.0：テーブル内の自動採番

テーブル内の「文字列（1行）」フィールドを採番対象として選択できる改修版を試験提供します。行ごとの番号は 接頭辞 + レコードID + - + 行ID で確定し、行の移動や削除で既存番号を書き換えない設計です。テーブルの行IDを保持したAPI更新処理を実装しています。

重要：自動試験22件は合格していますが、kintone実テーブル上での導入・更新検証はまだ完了していません。業務アプリに導入せず、検証専用アプリでお試しください。通常フィールド向けの安定版v1.0.0も継続提供しています。

02SETUP導入手順

1. フィールドを用意する

対象アプリに「文字列（1行）」フィールドを追加します。採番が保存後に確定するため、必須項目にせず、ルックアップも設定しないでください。採番を行うユーザーにレコードとフィールドへの編集権限が必要です。

2. プラグインを読み込む

kintoneのシステム管理から「プラグイン」を開き、ダウンロードした resoarc-auto-number-v1.0.0.zip を登録します。アプリの設定 ＞ プラグインで「追加する」から本プラグインを選びます。

3. 採番ルールを設定・反映する

プラグインの設定で採番先フィールド、接頭辞、桁数（3〜12）、開始番号を指定し、保存後にアプリを更新します。接頭辞 RA-、6桁、開始1の場合、レコードID 3 は RA-000003 になります。

4. 新規レコードで確認する

ブラウザーからレコードを作成して保存します。保存後のAPI更新が失敗した場合、詳細画面に「採番を再試行」ボタンが表示されます。番号が発行されているレコードは上書きしません。

03SPECIFICATION仕様と制限

採番方式

接頭辞 + (レコードID + 開始番号 - 1) をゼロ埋めして生成します。連続したレコードIDを取り合うカウンター方式ではないため、同一アプリ・同一設定で自動生成する番号同士の競合を避けられます。ただし、欠番が発生することがあります。削除済み番号も再利用しません。

対応範囲

PC・モバイルのkintoneブラウザー画面からの新規登録を対象とします。保存後にkintone自身のREST APIで採番フィールドを更新するため、権限や通信状態によって採番に失敗する場合があります。

CSVインポートや外部REST APIから登録したレコードには、新規作成のブラウザーイベントが発生しないため自動付番されません。空欄の既存レコードは詳細画面の再試行機能を利用してください。

番号の一意性と運用上の注意

手動入力・別の採番処理・過去の設定値からの重複まで防ぐものではありません。採番ルールを運用途中で変更すると番号体系が混在します。番号の欠番禁止、日付リセット、アプリ横断の一意性は対象外です。

データ通信・利用条件

プラグインはkintoneの同一環境に対してGET/PUT APIを使用します。ResoArcの外部サーバーにレコード内容を送信する処理はありません。JavaScriptソースはMIT Licenseで公開しています。サポートの応答時間や結果の完全性は保証しません。

確認済みテスト

kintone開発環境の専用アプリで連続3件の作成・採番が成功し、RA-000001、RA-000002、RA-000003 を確認しました。採番済みフィールドが編集不可になることも確認しています。JavaScriptの単体・モック試験は11件合格しています。

実際の多数同時アクセス、異なる権限での運用、すべてのモバイル環境、CSV経由で作成したレコードの再試行は未検証です。第三者による認証・セキュリティ監査を受けたという意味ではありません。
