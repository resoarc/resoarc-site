## Delivered automated Guardian candidate gates

- `release/guardian_beta_acceptance.py`: execute actual Guardian with **temporary** Ed25519 keys and signed feeds. Verify normal display, feed versions, replay/rollback, tampered and extra fields, invalid public key, oversize input, concurrent lock and state corruption. Temporary private keys are discarded.
- `protocol/display_control_test.go`: signed messages with terminal ESC, CR, LF, TAB, Unicode bidi controls and invisible formatting cannot be printed as trusted display text. Ordinary Japanese notices remain valid.
- `release/guardian_candidate_package.py`: cross-build Windows amd64, Linux amd64 and ARM64, with SHA-256 manifests. Deliberately **UNSIGNED CI ONLY**, not a release package. The CI uploads **reports and digests only, never executables or test private keys**.
- `release/release_gate.py`: fail-closed evaluation of 11 independent evidence items. True booleans without evidence references cannot pass. Even complete evidence never performs a GitHub release, grants public enrollment or signs a binary.
- `.github/workflows/trapnet-guardian-release-gates.yml`: run these checks on PR/branch updates.

### Guardian must pass before LIMITED beta

1. Exact pinned source revision reviewed; all CI and clean-source checks green on the same revision.
2. Verifiable build provenance and **independently verified publisher signature**, distinct from warning-feed signing authority. A SHA-256 checksum alone is not signing.
3. Install/uninstall and rollback recovery tested on every advertised OS, including damaged local state and stale locks. Installer asks no administrator access where unnecessary.
4. Pinned feed signer key custody, emergency revocation, rotation and anti-rollback demonstrated across a real upgrade.
5. Read-only and no incoming listener, remote-command interpreter, auto-block, or forced client telemetry confirmed in code and a sandbox.
6. Privacy notice, vulnerability contact, data retention, known limitations and emergency stop procedure made user-visible.
7. Independent security review and named human release approval recorded for the exact candidate digest.

Beta Guardian is an **informational viewer**, not a network security guarantee.

## Sonar source-to-runtime and isolation gates

On the VPS, read-only checks on 2026-10-27 observed three running containers (Web, Cowrie/SSH, edge), active private aggregation timer, HTTP 200 local Web health and no reported boundary violations.

We compared the existing deployed runtime to the Draft branch: `sonar_profiles.py`,
`sonar_hardening.py` and `sonar_snapshot.py` now match runtime by **exact SHA-256** after safely synchronizing the latter two. The full production Web-decoy logic, its sensitive deployment configuration, and the systemd timer require separate audit before a public source-to-runtime parity claim.

The `release/sonar_parity.py` audit inventories exactly five runtime source files and can compare them with a **separately reviewed, private, independently retained** manifest. Never commit private deployment manifests or raw telemetry to this public repository. A newly created on-host hash inventory by itself is NOT independent provenance.

Additional non-negotiable Sonar gates:
- A dedicated router-enforced isolated segment, no protected LAN or NAS routing; prove reachability controls against an **actually listening** target and preserve independent management access. A mere timeout on a closed port proves nothing.
- Decoy container/resource limits; no Docker socket access, secret mounts, privileged process or lateral network routes. Test container-process compromise in a disposable lab with no real secrets or public impact.
- Stop/start, storage exhaustion, full power loss and restored backups on a disposable host. Replay protection and Witness integrity must survive operator recovery.
- Document raw IP/user-agent/command log retention and disposal, access controls, incident response and withdrawal of operator consent.
- No real credentials or vulnerabilities in fake response objects. Always use inert tokens.

**Stick PC on the residential LAN remains NOT ELIGIBLE for a public Sensor** due to previously measured direct RDP reachability to the main PC.

## Separate later gates for a general participation network

Independent real operators with verifiable ownership; anti-Sybil correlation that never treats signature as truth; Witness off-HUB independent custody and separately published historical anchor; operator key rotation and emergency revocation; signed and rollback-resistant update pipeline; malicious/fake observer audit, false-positive monitoring and emergency pause. No global automatic blocking is required for the first public version.

## Next decision, not a promise of launch

1. Guardian candidate: finish binary signature and provenance, supported-OS install/uninstall, key rollover simulation and independent review; then authorize limited beta explicitly.
2. Sonar: privately archive and audit deployment source, document exact parity; then prove isolation and destructive recovery before distributing an operator-run honeypot.
3. General TrapNet: independent real operator and Witness custody trial before public enrollment.

All release evidence should link a **specific revision and artifact digest**. No single green workflow or self-attestation is sufficient for GO.
