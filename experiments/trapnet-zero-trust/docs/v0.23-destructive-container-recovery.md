# TrapNet v0.23: disposable Cowrie destructive-container recovery trial

**Scope:** Experimental read-only lab only. Never target production Cowrie.

v0.22 proved an internal SSH banner, JSON connection logging and a
*same-container* restart under an explicitly read-only root/config and
private writable var. That was not sufficient: removing/recreating a
container might accidentally destroy Docker-managed volume state.

v0.23 runs the complete lifecycle with **only** an immutable local image
SHA, image-default config, an isolated private host-owned var directory,
`--network none`, zero ports, no elevated capabilities, and bounded
CPU/memory/PIDs:

1. First fresh container start, valid Cowrie JSON connection events.
2. Graceful stop and **remove the container and anonymous volumes**.
   Preserve only an external private `/var` bind mount.
3. A brand-new container ID, with the exact same restricted config and
   private data mounts, must accept a new simulated SSH connection.
   Existing JSON bytes must remain a prefix and connection count must rise.
4. **SIGKILL** the disposable container, restart and verify that the
   previously recorded JSON bytes remain intact and a new connection is
   recorded. This is process-crash simulation, not a host power-loss test.
5. Validate readable JSON and a conservative test-data size cap,
   remove every lab container and private test directory and return a
   machine-readable result with only aggregate counts and booleans.

CLI: `python3 sonar/cowrie_recreate_recovery.py --image-id sha256:<64-hex>`.
This must only be run by an authorized operator with Docker rights and
a preinstalled immutable image. CI runs mock-based Python regression tests,
not a privileged Docker or Internet-exposed honeyservice.

**Limitations / safety gates:** the final size check is not a disk quota,
disk-full handling is NOT validated, `docker kill` does not reproduce a
power interruption or journal loss, no actual production config/observations
are copied, no off-box backup/recovery is proven, host egress/firewall and
independent human review remain pending. A test passing does not authorize
production deployment or public beta.

The public-facing production Sonar remains untouched; the ongoing
Guardian and Sonar release gates stay HOLD.
