# TrapNet v0.21: read-only host mount scope

Status: Draft PR only. This change does not reconfigure or restart any live sensor.

The existing Sonar boundary audit checked writable paths but accepted any
read-only bind destination. That is insufficient: a readonly mount can still
expose confidential host data to an instrumented decoy.

The audit now accepts only these exact readonly bind destinations:
- Web: `/app`
- Edge: `/usr/local/etc/haproxy/haproxy.cfg`
- Cowrie: `/cowrie/cowrie-git/etc` or
  `/cowrie/cowrie-git/etc/cowrie.cfg`

For Cowrie, only `/cowrie/cowrie-git/var` may be a writable mount.
All other writable or readonly mount destinations are rejected, including
anonymous readonly volumes. The result explicitly states that allowed
host **source** ownership/content and image-declared volume overrides
have NOT been verified: `false` for both. The literal source location
and provenance must be privately reviewed before self-hosted beta.

Earlier live inspection showed exactly the expected readonly destinations,
but Cowrie has a writable settings volume and writable root filesystem.
Those two constraints remain HOLD.

The previously isolated Cowrie read-only trial also revealed broken JSON
logging due to missing `var/log/cowrie` within fresh private tmpfs.
Functional startup, bounded log retention, recovery and real egress isolation
remain unproven. Human review, trusted publisher signatures and release
approval are separate gates. No automatic blocking is enabled.

Local Windows regression: 35 cases, 34 passed, 1 symlink-privilege skip.
Linux CI must run the entire suite, including the symlink case.
