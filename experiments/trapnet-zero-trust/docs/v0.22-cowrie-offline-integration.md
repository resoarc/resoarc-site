# TrapNet v0.22: verified offline read-only Cowrie integration

**Result:** On the authorized production VPS, a *separate disposable container*
using the existing pinned local image ID (`sha256:17191d19...`) completed
read-only start, internal SSH banner, JSON connection logs, restart and
log persistence. It had `--network none`, no published ports,
non-root UID 999, a read-only root and config bind mount, a private var
bind mount and bounded CPU, RAM and PID count.

Sanitized measured result: **3 JSON events before restart, 6 after restart**.
The trial container and private temporary filesystem were removed.
No production container, private Cowrie config, raw attack logs, public
interface or listener was modified or exported. This proves the four
functional checks for that exact image at this point in time only.

## Previous blocker resolved

The former read-only Cowrie trial mounted a fresh tmpfs over the `var`
directory, masking `log/cowrie` and causing a JSON output failure. Another
trial relied on `/bin/sh`, which is not guaranteed to exist in the
distroless image. Neither approach correctly initialized all writable paths
before execution.

The successful approach copies only **image-default** Cowrie config from a
throwaway *stopped* container, prepares private `/var/log/cowrie`,
`/var/run` and `/var/lib/cowrie` on the host, assigns UID 999 to the
private data area, then starts a separate no-network container with exact
explicit `/etc` (read-only) and `/var` (writable) mounts. This suppresses
the image's anonymous writable `/etc` volume, which is a major improvement
over the present production setup.

## Reproduction

A verified **existing** immutable local Docker image ID is required. Run
only on a disposable or expressly authorized Linux test host with Docker
privileges and enough free disk. The test does **not pull images**, accept
ports, access the production Cowrie container, use external addresses or
publish logs.

```sh
python3 sonar/cowrie_offline_integration.py --image-id sha256:<64-lowercase-hex>
```

A green result proves its narrow list of checks, not full confinement or
security. The same test container is stopped/restarted; host reboot,
read-only configuration source review, durable log retention across a real
disk outage, Docker daemon compromise and actual firewall egress isolation
are outside its scope. Do not automatically promote this into the
production stack. The public beta remains HOLD until private source review,
staging data/backup, egress and destructive recovery tests and independent
human review are complete.

Separate offline Python unit tests exercise immutable image ID checks,
volume allowlist, JSON event parsing and container isolation fail-closed.
Do not put raw Docker inspect, user-agent, source IP or Cowrie logs into
GitHub evidence or CI artifacts.
