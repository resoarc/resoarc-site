# TrapNet v0.24: disposable private-var backup and restore drill

## Real-world trial target

Continue v0.23's protected experiment after delete/recreate and SIGKILL
recovery. **Stop and remove only the disposable test Cowrie container**,
then capture an SHA-256 manifest of its private `/var` tree using a strict
file-count and 8 MiB size ceiling. Symlinks, hardlinks, non-regular files,
out-of-scope paths and changed files fail closed.

Copy the private test data to a temporary offline backup directory inside
the experiment root; compare every file's SHA-256 and size. Delete the
**test-only** `/var` directory, verify the backup is unchanged, restore
with the expected UID 999, and confirm the old JSON event stream is
byte-for-byte identical. Start a completely new container from the
immutable image, verify a fresh internal SSH handshake, and require more
JSON connect events without losing any previous record.

The script still uses `--network none`, no published ports, read-only root
and config, non-root UID 999, resource caps and disposable test paths.
`cowrie_lab_backup.py` is **not** a production backup program; it does not
access, migrate or publish real Cowrie logs or configuration.

## Limits, not a production claim

The 8 MiB backup maximum is a **test rejection threshold**, not a
filesystem quota or guaranteed safe rotation. Data is copied within the
same physical VPS; offsite disaster recovery, storage fsync/journaling
guarantees, real power loss, disk exhaustion, credential storage,
network lateral movement and human security review are NOT proven.
No real production Cowrie data is backed up, deleted or overwritten.
Do not publish telemetry from experiments, and do not authorize
self-hosted Sonar beta based solely on this trial.
