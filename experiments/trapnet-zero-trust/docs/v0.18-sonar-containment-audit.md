# Sonar offline container-boundary audit (v0.18)

**Draft-only, no production writes.** Run `python3 sonar/containment_audit.py --live`
from the development checkout on the VPS only with an already authorized
read-only Docker inspect route. Do not grant a public sensor or AI reviewer
the Docker socket. The script does not take action on containers.

The audit reads three specified containers (web, ssh/Cowrie, edge/HAProxy)
and emits only a small allowlisted boolean assessment: nonroot,
nonprivileged, capability restrictions, no new privileges, no host net mode,
no Docker socket mount, bounded CPU/memory/PIDs, read-only root and running.
Raw `docker inspect` JSON may include credentials and internal addresses.
**Never upload raw JSON**; output deliberately omits Env, paths, IPs, image
IDs, bind mount sources and runtime secrets.

Any failed static control means `passed_static_container_controls=false`.
Even a full pass emits `public_beta_ready=false`, because `docker inspect`
cannot prove external firewall egress restrictions, protection from a real
container escape, complete loss of services, actual network lateral movement,
file mount access policy or restoration after power/storage failure.

Earlier production measurements indicated that **Cowrie's root filesystem
was writable**. Investigate exact required paths and rootless/readonly
alternatives in a disposable isolated staging environment. Do not abruptly
switch the existing live SSH honeypot to read-only, because it may require
writes to logs or state. Take backups and regression-test recovery before
any staged or production change.

The actual host's audit result must be recorded by a human-reviewed,
independently timestamped evidence file in a private operations repository;
a GitHub CI fixture test does not certify the VPS deployment.
