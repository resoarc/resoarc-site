# TrapNet v0.25b: verify health transition during synthetic disk pressure

This supplement to v0.25 integrates the **actual checked-in**
`cowrie_log_health.py` in the disposable Cowrie test container. The host
passes a trusted read-only Python checker over `docker exec -i` standard
input. No script, secret, probe result or tool is installed on the production
Cowrie, and no writable root access is added to the lab container.

Required transition:

1. **HEALTHY** with live JSON events on a verified 8MiB isolated tmpfs.
2. **UNHEALTHY** due to the explicit `FREE_SPACE_LOW` failure when the
   synthetic pressure writer reaches `ENOSPC`. A running SSH server does
   **not** override a failing storage health result.
3. **HEALTHY** again once the test-only filler has been removed and a
   new JSON connection event is appended.

CI separately checks that expected low-space exit status is parsed and that
malformed checker responses or unexpected errors fail closed.
This is a functional simulation, not production alerting: there is no
installed exporter, systemd alert, paging/on-call integration or autonomous
service stopper. Never send raw Cowrie events to a third-party reviewer.

The production Cowrie root and /etc volume remain writable. No production
deployment, public beta or network/firewall changes are authorized.
