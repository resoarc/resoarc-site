# TrapNet v0.4 off-HUB evidence witness (experimental)

**Development only. Do not expose HUB to the Internet.** This feature provides
an external *cryptographic consistency witness* for evidence already logged by
HUB; it does not confirm that reported events occurred or identify attackers.

## Roles and trust boundary

- **HUB:** persists `ledger.jsonl` and `ledger.jsonl.head`; contains no witness private key.
- **Witness operator:** controls a **different, trusted host or offline machine**, copies a consistent *closed* snapshot of both files, independently measures the chained evidence and signs a new checkpoint. Operates the append-only `history.jsonl` and the signing private key, neither mounted on HUB.
- **Auditor:** verifies the witness public key, the signed checkpoint chain, each previously witnessed ledger boundary, and a latest tip hash pinned out-of-band.

A witness signature means "these exact ledger bytes were committed as of this
checkpoint". It is not proof that the underlying observations are true. A HUB
compromised **before the first witness** can fabricate a self-consistent first
snapshot, which the witness cannot distinguish from genuine events.

## Offline workflow

1. On HUB, **stop the writer**. Confirm process exit and preserve the original ledger and `.head`; never snapshot a concurrently changing pair. Copy both files to the offline witness workstation with an authenticated transfer. The `.head` must remain adjacent to the copied ledger.
2. On an offline workstation, generate a **dedicated** witness keypair using `go run ./cmd/keygen -out witness-root`. This key must never be copied to HUB and must not be reused for feed, Sensor or revocation signing.
3. Inspect the first snapshot and history location before creating the *only* genesis entry:

   ```sh
   go run ./cmd/witness -mode attest -ledger hub-copy.jsonl \
     -history history.jsonl -key witness-root/private.hex -bootstrap-history
   ```

4. Independently pin the printed `tip=` SHA-256, for example in a separately administered signed record or protected offline notebook. The private key + witness history alone **do not** prevent rollback of a valid signed suffix.
5. On the next **new** closed snapshot, pass the *previous pinned tip*:

   ```sh
   go run ./cmd/witness -mode attest -ledger next-hub-copy.jsonl \
     -history history.jsonl -key witness-root/private.hex \
     -expected-tip <PREVIOUS_INDEPENDENTLY_PINNED_TIP>
   ```

6. Independently pin the new tip before the next attestation. A third party can audit a matching snapshot with:

   ```sh
   go run ./cmd/witness -mode verify -ledger next-hub-copy.jsonl \
     -history history.jsonl -pub witness-root/public.hex \
     -expected-tip <LATEST_INDEPENDENTLY_PINNED_TIP>
   ```

The CLI refuses continuation without a pinned previous tip, and verification
without an independent latest tip. Genesis requires an explicit flag and must
**never** be used to recover from missing history. A stale writer lock must be
investigated; do not clear it until process exit and storage integrity are
confirmed.

## Adversarial acceptance and limits

| Test | Expected outcome |
| --- | --- |
| HUB edits one ledger row and regenerates `.head` | Historical signed boundary disagrees: reject |
| HUB truncates ledger, loses `.head`, or presents incomplete tail | Reject |
| Witness history record tampered or reordered | Signature/chain verification fails |
| Old valid witness history restored | Reject if latest trusted tip is pinned outside history |
| Operator tries to sign an update without independently pinned tip | Reject |
| HUB lies before any witness entry, or colludes with witness | Not detectable solely by these signatures |
| Witness signer private key is stolen | Future witness trust compromised; recovery needs an independently audited trust-root transition |
| HUB deletes records after last witness but before next | Historical commitment protects only *previously witnessed* rows; detecting unreported later rows requires independent collection/availability monitoring |

**Recovery:** freeze operations, copy originals read-only, compare latest independent
pin with locally available history, verify offline snapshots and signed history,
then investigate the first mismatch. Never auto-truncate or re-bootstrap a broken
history. A separate, governed key-rotation procedure, immutable remote
publication, multi-operator witnesses, disk crash tests, and five-node isolation
lab are future security gates, not completed features.
