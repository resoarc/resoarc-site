# TrapNet Guardian v0.17: trust-anchor and source revision hardening

**Status:** Draft PR #32; public release HOLD. No live Sonar, HUB, firewall, network listener or private deployment key changes.

## Guardian Root continuity

The first locally accepted Root Ed25519 public key is SHA-256 pinned to Guardian's fail-closed anti-rollback state. The state also records the signed warning feed and signer-policy version/digests. A substitute Root cannot authorize a newer signer policy merely by providing a higher version. Revoked signer tests continue to pass under the original Root. Beta CLI mode uses this pinning; older laboratory helpers remain separate but cannot bypass a root-bound state.

Existing policy states without Root fingerprints must undergo **explicit, manually reviewed trust migration**. Do not delete or overwrite an installed state simply to clear an error. A compromised local administrator able to erase state remains outside this guarantee; protected offline state backups and secure Root public-key distribution are still required.

## Signed release source identity

The separate distribution-key-signed Guardian release metadata now requires a 40-digit lowercase `source_commit_sha` alongside version, validity interval, exact binary filenames, sizes and SHA-256. Altering the source identity invalidates the signature. This is provenance **identification only**, not independent proof that the binary was compiled from that source. CI uses temporary signer keys and synthetic artifacts, never production release credentials.
