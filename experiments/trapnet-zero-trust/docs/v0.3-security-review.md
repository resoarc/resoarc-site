# TrapNet v0.3 security change review (development only)

Date: 2026-10-27. This is an internal engineering review and not an independent audit.

## Security boundaries unchanged

- Only `127.0.0.1:8788` may be used by this MVP HUB; no public enrollment.
- Sensor submits authenticated **unverified claims**, not established attack facts.
- Guardian displays signed short text warnings; there is no firewall change,
  remote shell, remote script or autonomous blocklist.
- The revocation signing private key belongs on an **offline machine** and is
  deliberately different from Sensor/feed signing keys.

## Ledger protections introduced

`ledger.jsonl.head` contains a revision, row count and a chained SHA-256 digest:

```
H[0] = 32 zero bytes
H[i] = SHA256(H[i-1] || uint64_be(len(row_including_newline)) || row)
```

A signed report is acknowledged only after the ledger row and checkpoint are
synced. Missing head, invalid trailing newline, chain mismatch or storage
errors cause the receiver to fail closed. A `ledger.jsonl.lock` file prevents
simultaneous local HUB writers. **On a crash, do not automatically remove a
stale lock.** Preserve copies of both files before reviewing and recovering.

Known limit: The checkpoint is on the same host. An attacker with OS-level
write access to both ledger and checkpoint can forge a consistent chain.
Publish externally witnessed, threshold-signed checkpoint roots before
claiming tamper resistance against compromised HUB administrators. The MVP
has no bounded retention and must not be used as a production evidence store.

## Revocation protections introduced

- Optional local JSON snapshots, signed offline with an independent Ed25519
  root, are checked **on every report**. Snapshot validity is <=24h; signer
  defaults to a 12h lease.
- The complete allowlisted revocation set is versioned. Version must not
  decrease; equal version with different content is refused. The last accepted
  version/digest persists in `revocations.signed.json.state`.
- A missing/expired/invalid/symlinked snapshot returns HTTP 503 (closed).
  A listed node returns HTTP 403. Tests cover removal, replacement, replay,
  tampering, expiry and concurrent valid reports.

Known limit: A privileged local attacker capable of rolling back the revocation
state file can also weaken version protection. Add independently protected
monotonic state and offline-root rotation before public use. Atomic delivery of
signed revocation files is the responsibility of the local operator; partial
updates fail closed. A revoked node may have contributed historical **false**
observations, and those must be marked for investigation separately.

## Guardian concurrent state protections

Guardian obtains `guardian-state.json.lock` with O_EXCL before examining or
committing monotonic feed state. Concurrent writers fail closed, and the lock
remains after a process crash until an operator investigates. This is a
state-consistency lock and is **not** a tamper-resistant store against a
privileged local attacker.

## Evidence and acceptance

Run from `experiments/trapnet-zero-trust`:

```
go test -race ./...
go vet ./...
GOOS=windows GOARCH=amd64 go build ./cmd/hub
GOOS=linux GOARCH=amd64 go build ./cmd/hub
GOOS=linux GOARCH=arm64 go build ./cmd/hub
```

Tests cover ledger rewrite, missing checkpoint, incomplete tail, closed file
storage fault, single-writer lock, signed revocation stale/tampered/expired
failures and hot reload, concurrency, and Guardian lock.

## Outstanding HOLD gates

- Signed, externally witnessed checkpoints and operational recovery drills
- Bounded ledger retention with replay-resistance-preserving compaction
- Signed key rotation and safely pinned offline trust-root transitions
- Five independently controlled nodes in a fully isolated network
- Privacy review, independent security assessment and safe updater/TUF
- Failure injection for power loss/disk full on real target filesystems

Do not merge/deploy to public hosts based solely on passing local tests.
