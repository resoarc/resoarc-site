# TrapNet v0.13: physical off-HUB Witness drill (2026-10-27)

**Status: development validation only.** No production HUB ledger, private SSH key, production node identifier, actual customer log or unreviewed Internet observation was used.

## Goal and trust boundary

Demonstrate that the node responsible for receiving evidence and the node holding the Witness signing private key can be on **different physical hosts**. The exercise used an existing VPS as the synthetic evidence producer and a separate Windows main PC as the Witness. Only a closed evidence snapshot (`ledger.jsonl` with adjacent `.head`), a fake trust registry and test binaries were transferred over SSH. **The Witness signing private key never left the main PC.**

The generator `cmd/lab-fixture` is deliberately synthetic and offline-only:
- Generates three separately signed report rows with distinct ephemeral Ed25519 Sensor keys.
- Uses two **fictional** reviewed operator groups, with two Sensors in the first group. Group names are fixtures and do **not** represent genuine independent operators.
- Produces a consistent chained `synthetic-ledger.jsonl.head`, a trust registry and SHA-256 inventory.
- Does not persist the ephemeral node signing keys or send messages to any real HUB.
- Refuses to overwrite an existing fixture directory.

The operator independently pinned the transferred files' hashes on the receiving host; that proves byte equality with the exported fixture, **not** that the VPS could not have fabricated that fixture before transfer.

## Verified exercise

1. Built Linux fixture producer and Windows Witness, key generator and `corroborate` executables in an isolated build container.
2. Generated three synthetic signed reports and a CLOSED chained ledger on the VPS.
3. Copied the fixture and Windows executables over authenticated SSH to the main PC; verified **all binaries and evidence file SHA-256 checksums** against transfer manifests.
4. Generated the Witness Ed25519 key **on the main PC**, attested the closed ledger, and verified the signed Witness history using a separately saved pinned tip.
5. Ran `cmd/corroborate` against the same closed snapshot with seven mandatory flags. The only case returned `multi_operator_candidate_for_manual_review`; automatic blocking, feed publication and operator-independence assertions remained false.
6. Ran five negative tests with deliberate temporary copies, each refusing to produce a case: wrong externally pinned tip; validly rehashed evidence with an unwitnessed extra row and recomputed local `.head`; one modified signed report with recomputed local `.head` and new file hash; truncated history; substituted Witness public key.
7. Verified the signed history again, then deleted the **test-only Witness signing private key** on the main PC. Retained the signed history, public key, anchored tip and a privacy-safe results record in `Documents/ResoArc/TrapNet/v13-crosshost-20261027` and `Documents/ResoArc/TrapNet/WitnessAnchors`. **These locations are on one Windows host, not a genuinely independent/immutable external anchor.**

## Reproduce in a permitted isolated lab

~~~bash
go run ./cmd/lab-fixture -out /tmp/new-synthetic-evidence-dir
~~~

Transfer only `synthetic-ledger.jsonl`, `synthetic-ledger.jsonl.head`, `reviewed-trust.json`, `SHA256SUMS` and the offline verifier binaries to an independent workstation. Verify the checksums *before* using any evidence. On that other workstation create a disposable signing key, attest via `cmd/witness -mode attest`, and run `cmd/corroborate` with separately stored ledger/trust hashes, history, Witness public key, and pinned Witness tip. **Never** send Witness private keys to the evidence-producing machine.

This was a two-host physical drill with three fake Sensors. It **does not** prove true independent Sensor operators, secure transfer of real production logs, third-party trust governance, durable offsite key recovery, or protection from a malicious/compromised HUB before initial witnessing.

## Operational gates still open

- An authorized, immutable **closed copy of real production data** must undergo a separately approved privacy and retention review before any real-data drill.
- Witness key custody requires encrypted storage, durable independently controlled offsite anchor, rotation, revocation and recovery procedures.
- Provide a second independently controlled operator, not just additional keys labelled with different groups.
- Deny host-to-host lateral movement before running any public-facing Sensor on the same residential LAN as important PCs/NAS.
- Production v3.2 Web/Cowrie telemetry remains running; v0.13 is **not installed on the production HUB** and PR #32 remains Draft.

The incident/forensic rule remains: **a valid signed observation is a statement attributable to a key, not proof of malicious intent or truth.**
