# TrapNet v0.25: bounded Cowrie log-pressure and preflight gates

**Draft, no public release, no production Cowrie changes.**

On 2026-10-28, an authorized VPS operator tested the existing immutable
Cowrie image in **8 MiB Docker local-driver tmpfs**, with isolated no-network
containers, no published ports, no production mounts, non-root UID 999 and
read-only root/config. Only synthetic strings were written to a uniquely
named test-volume pressure file.

Two live **disposable** experiments measured an exact 8,388,608-byte cap
and Linux `ENOSPC`. During the second experiment, Cowrie stayed running,
SSH banner replies continued, the pre-pressure connection counter rose
from **1 to 2** while the pressure file existed, and to **3** after the
synthetic file was deleted. Observed JSON events were **3 -> 6 -> 9**.
The test containers, tmpfs volume and scratch directory were removed.
This does not prove that *every* event is reliably logged under sustained
disk exhaustion. The observed success must not be mistaken for a production
retention, lossless recording, or fail-safe shutdown guarantee.

## Implementation

- `cowrie_log_pressure.py`: reproducible **off-line lab only**. Requires
  preinstalled immutable image SHA-256 and Docker privileges. Prepares
  image-default read-only config, bounded 8 MiB tmpfs var, an isolated
  Cowrie process, generates a loopback SSH client event, fills only the
  trial volume until ENOSPC, probes again, removes only its synthetic
  filler, and checks new JSON connection counts. A passed experiment
  never sets `release_approved=true`.
- `cowrie_log_health.py`: read-only fail-closed preflight for a **private
  test var**. Requires a proven bounded filesystem capacity, minimum
  free space, a regular non-symlink Cowrie JSON file and parseable bounded
  JSON lines. Returns only issue codes, free-space quantities and event
  counts, never raw attacker-origin records. It never edits, rotates,
  copies, deletes, uploads or blocks anything. A passing static preflight
  does **not** prove the logger is actively appending.
- New Python regression tests cover healthy/low-space/unbounded FS,
  malformed JSON, missing logs, symlink and invalid thresholds. GitHub
  CI runs Python mocks, not the privileged Docker pressure experiment.

## Open safety conditions

The existing production Cowrie still has a writable root and writable
configuration volume. Its backing store is much larger than the 8 MiB
lab, with no audited enforceable per-Cowrie cap. A high free-space
number is not a quota. Before public Sonar beta, implement approved
log retention/rotation, verified low-space alerts, crash/power-loss
and offsite restore, actual egress/firewall isolation and independent
human security review. Do not promote or alter production from these
experiments alone.
