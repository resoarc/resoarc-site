# TrapNet v0.11: Independent observation and cautious corroboration

Status: **Draft / operator-only evaluation**, not a network service or public feed.

## 1. Offline corroboration

`correlate` / `cmd/corroborate` takes a separately preserved, closed HUB ledger and a **manually reviewed** trust registry. It validates node Ed25519 signatures using the existing TrapNet protocol; rejects unknown keys, stale/future receipt times, duplicate node/event IDs and malformed JSON; and groups reported fingerprints by event kind and ten-minute receipt-time window.

A node's `operator_group` may be set only by an administrator who verified actual organizational control independently. **Never** derive this group from a report, IP address, sensor name or public node ID. Multiple sensors in the same group count as one operator. Even two different reviewed groups produce only `multi_operator_candidate_for_manual_review`; distinct human operators, attack intent and the correctness of a fingerprint are **not cryptographically proven**.

The CLI requires two separate SHA-256 values of a trusted snapshot and trust registry. Obtain and pin these values on an independently controlled workstation, not from a possibly compromised HUB after the incident. A hash alone is not an attestation or evidence of unmodified history; first verify existing Witness attestations and source chain. **Never** run triage against a live, mutating HUB ledger.

Example, after independent snapshot / Witness review:

~~~bash
go run ./cmd/corroborate \
  -ledger /secure/offline/evidence.jsonl \
  -ledger-sha256 YOUR_INDEPENDENTLY_PINNED_64_HEX_HASH \
  -trust /secure/offline/reviewed-nodes.json \
  -trust-sha256 YOUR_OTHER_PINNED_64_HEX_HASH
~~~

Trust JSON is a map of node-id to `{"public_key":"<ed25519-hex>","operator_group":"operator-one","reviewed":true}`. Retain this file under restricted access, **never put actual key maps or host locations in a public repository**.

Output contains coarse bands and ephemeral `case-001` labels, not fingerprints, public keys, actual operator identifiers, or node IDs. Every record remains *an authenticated claim, not verified attack truth*. No automatic blocking, feed signing, Guardian commands or webhook side effects exist.

## 2. Passive-source importer

`sonar/passive_import.py` can inspect a locally supplied authorized HTTP access log (JSONL or common access-log format), including a separate reverse proxy. It uses the current redacting `sonar_hardening.aggregate` code, suppressing small cohorts. It does not open inbound ports, require cloud credentials, run arbitrary downloaded code, or automatically forward the data.

~~~bash
cd sonar
python3 passive_import.py --input /secure/export/access.jsonl \
  --source-kind authorized_reverse_proxy --authorized \
  --output /secure/private/passive-summary.json
~~~

Use only logs from systems you own or have explicitly been authorized to collect. This `--authorized` flag records operator intent; **it cannot technically establish legal consent**. Input files are bounded, symlinks rejected, and the summary is written owner-read-only. Raw log retention, access control and deletion must be separately governed by each source system.

The source is an *independent telemetry type*, not proof of an independently owned geographical sensor. Multiple deployment operators and physically isolated hosts have **not** been established by this adapter.
