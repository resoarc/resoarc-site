## Design rationale and review

- Iris (GPT-6) implemented a disposable GitHub-hosted Ubuntu Docker probe, synthetically exercising the v0.54 AI-response quarantine, not real traffic, model execution, or production services.
- Gemini 3.8 Flash High independently flagged schema sabotage, instruction spoofing, Unicode obfuscation, oversized data and exhaustion. It stressed that OS containment cannot fix application logic failures or prevent stdout/memory leaks. Its initial attempt was auto-denied by the model bridge because it requested an unavailable command permission; a narrower, text-only request succeeded without permissions relaxation.
- Claude Sonnet 4.6 reviewed the isolation proposal and highlighted no-network limitations, temporary file availability, /proc information, inherited credentials, cgroups version differences and misleading "cannot create a socket" claims. Our test therefore checks non-loopback connection denial and loopback-only interfaces, not socket creation prohibition.

## Linux CI probe

The new `.github/workflows/trapnet-e2-oci-isolation.yml` job uses a disposable, host-downloaded `python:3.12-alpine` image identified at runtime by immutable image ID. Docker isolation settings:

- `--network none` (no externally routed interface, local loopback may still exist);
- `--read-only` container root, public repository bind-mounted read-only;
- `--user 65534:65534` nonroot;
- `--cap-drop ALL` and `--security-opt no-new-privileges`;
- Docker default seccomp filter, `--pids-limit 64`, `--memory 128m`, `--cpus 1`;
- tiny `/tmp` tmpfs with `noexec,nosuid`, bounded to 4 MiB. We expressly acknowledge temporary files are writable there;
- no secret, Docker socket, credential or host-system mounts; no provider API environment variable inherited.

`lab/ai_container_isolation_probe.py` runs inside that container and asserts observable UID/GID, root/source mount read-only flags, no-new-privileges, empty effective capabilities, seccomp active, cgroup limits, loopback-only interfaces, unsuccessful TEST-NET-1 TCP connection and denied source/root writes. It additionally exercises the exact `ai_response_quarantine.process_json` function with a synthetic privacy-safe input and verifies 1 safe enum advisory accepted as quarantine-only while 12 malformed or privilege-seeking synthetic responses are refused. The synthetic input now originates from **11 fake HTTP/JSON log records** (including role/command-like decoy fields) processed by the actual authorized `passive_import.process` adapter, followed by `to_advisory_packet` and `ai_response_quarantine.process_json`. The probe asserts anonymization, fixed aggregate bands, mandatory human review and no HUB notification. The output is deterministic, privacy-safe JSON without raw model text. CI uploads an evidence artifact and checks the pass status.

Local Windows validation: Python source compiles, and the portable synthetic model-boundary subtest executed with **1 accepted / 12 rejected**, with no model call or host service interaction. OS isolation assertions deliberately require Linux Docker and cannot be declared PASS on Windows.

## Limits, not claims

- The CI runner host may reach the network; only the disposable probe container is configured to have no external network. The test does not cover a live model service, source provenance, or the entire production process tree.
- `--network none` does not prevent local loopback I/O; `--read-only` does not stop writes to the deliberately bounded /tmp tmpfs.
- This is not a sandbox-escape penetration test and does not prove kernel exploits impossible. Docker daemon and GitHub runner privilege are outside this proof boundary. A container can start child processes inside its limits; no general command-execution denial is claimed.
- The test confirms permissions of a synthetic offline environment, not the eventual AI hosting platform. All data were generated locally as fake aggregate metadata. No private keys or real attack logs are transmitted.
- Third-party human validation, actual operator separation and production-equivalent Sonar->AI->HUB->Guardian are still missing.
