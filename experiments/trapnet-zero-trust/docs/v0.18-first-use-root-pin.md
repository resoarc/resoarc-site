# TrapNet Guardian v0.18: first-use Root identity proof

**Draft PR #32, development-only. No public Guardian release and no production Sonar change.**

## The specific threat

Pinning a Root key *after* its first use is trust-on-first-use (TOFU). It cannot
detect an attacker-supplied Root key during initial installation. As a result,
correct verification of the attacker's signed signer-policy is not sufficient
to establish that the publisher intended the policy.

## Implemented mitigation

Guardian beta binaries (built with `-ldflags=-X main.requireRootPolicy=true`)
now **refuse to process any feed unless all three are supplied**:
`-rootpub`, `-policy`, `-root-sha256`.

The `-root-sha256` parameter is the 64-character lowercase hex SHA-256 of the
**raw, decoded 32-byte Ed25519 public key**, not the hex file, base64 text, or
policy JSON. Guardian compares that trusted fingerprint with the contents of
`-rootpub` *before* verifying the Root-signed policy and before creating
local anti-rollback state.

The fingerprint **must be obtained and checked independently**: e.g. from a
previously trusted release-signature channel, an operator-reviewed physical
handoff or another authenticated out-of-band channel. Printing a fingerprint
in the same untrusted download **does not establish trust**.

Usage when eventually approved for a signed beta (illustrative):

~~~text
guardian -feed signed-feed.json -policy signed-allowlist.json \
  -rootpub audited-publisher-root.hex \
  -root-sha256 <independently-verified-64-lowercase-hex> \
  -state guardian-state.json
~~~

The legacy `-pub` mode exists only in explicitly non-beta experimental
builds. Root state pinning and anti-rollback survive successful subsequent
updates. Root replacement, including emergency compromise recovery, still
requires separately approved migration procedures. Do not remove state merely
to clear Root mismatch errors.

## Acceptance evidence

The Linux and Windows CI run the real beta binary from the repo against
ephemeral test keys. They now check absent/mismatched Root fingerprint,
a fake validly signed Root **on an empty initial state**, positive first
enrollment using a separately pinned test fingerprint, authorized signer
rotation, and refusal of revoked keys and a later fake Root. Temporary private
keys are removed afterward.

**Limitations:** this is still an operator-supplied trust pin. It is not
hardware-backed trust, does not detect malicious binaries and does not
protect against an attacker with local administrator access able to replace
the executable, root pin and state together. Signed distribution, tested
recovery, provenance and independent human review remain HOLD gates.
