# TrapNet E2 v0.56: Real HUB and Guardian non-authority evidence (synthetic, CI only)

Date: 2026-11-02 JST. Stacked on v0.55 Draft PR #52. No main, VPS, public port, deployment, real packet capture or production key modification.

## Goal

Confirm that the **actual compiled Go HUB and Guardian executables**, not only the prior v0.54 Python quarantine parser and isolated synthetic v0.55 container, refuse hostile / unauthenticated **AI-derived data** without changing operational state. The test is a positive-control / negative-control experiment, not a production attack simulation.

## New assets

- `lab/ai_hub_guardian_fixture/main.go`: generates two ephemeral Ed25519 Sensor signers and two ephemeral Feed signers **in memory**, writing only public keys, an allowlist, and synthetic signed/unsigned/tampered fixture objects to an automatically deleted private temp directory. No private-key bytes are serialized, copied to a container host volume, or stored in CI artifacts.
- `lab/ai_hub_guardian_real_process_lab.py`: builds the existing Go HUB and Guardian or uses precompiled, read-only CI binaries. Launches a **real HUB process** on a randomly selected local `127.0.0.1` port, verifies its health and empty ledger, then submits model-output JSON, quarantined advisory JSON, extra-control fields, malformed and overlong payloads. Confirms all are refused and no ledger or checkpoint is created. Sends a correctly signed and allowlisted synthetic Sensor report as a positive control and confirms HTTP 202, exactly one durable ledger row and a checkpoint. Then tries unsigned, tampered, unregistered signer and replay payloads; confirms rejection and ledger/checkpoint hashes unchanged and HUB remains healthy.
- The same Python program launches the **real Guardian binary** repeatedly on fake JSON and signed feed files, using its explicitly **experimental legacy public-key mode** for the lab. Model outputs and malformed objects fail before a Guardian state file appears. A genuine signed informational feed is accepted and causes version 1 state. Unsigned, tampered, unknown-key and rollback feeds are refused, leaving the state digest unchanged. An exact same-version signed replay is idempotent and does not change the state.
- `.github/workflows/trapnet-e2-real-process-boundary.yml`: GitHub-hosted Linux job. Compiles the Go binaries with `CGO_ENABLED=0` on the build host, pulls an ephemeral Python image, then launches the **actual test inside a disposable Docker `--network none` container**, read-only root and source/binary mounts, nonroot UID 65534, all Linux capabilities dropped, `no-new-privileges`, PID and memory limits, default seccomp, small `noexec,nosuid` tmpfs. The only HTTP network endpoint is loopback inside the container. Publishes a short, synthetic-only JSON evidence artifact with no IDs or keys.

## Boundaries and limitations

- This tests actual Go processes, but only in an ephemeral container with synthetic data and intentionally ephemeral keys. It does not integrate a **deployed LLM process** into a production dataflow. The Python model output is a simulated well-formed advisory, not newly generated by a live model during this CI.
- Guardian uses experimental `-pub` mode as a narrow negative/positive process control; this is **not a verification of mandatory release-mode root-signed policy or independently pinned trust anchors**.
- HUB binds only 127.0.0.1 inside the container, not a publicly routable service. No remote scans, external destinations, firewall changes, or honeypot access occur.
- No conclusion that an attacker **holding a legitimate signing private key** can be blocked by signature validation alone; physical signing key separation and independent operator review remain crucial.
- CI test results cannot be claimed until exact PR-head Linux workflow passes. Even then **E2 remains PARTIAL, public release HOLD**, with independently operated real-world components and human audit still outstanding.

## Independent Claude review notes

Claude Sonnet 4.6 specifically highlighted that network namespaces do not defend against mistakenly mounted Docker sockets, that synthetic-key generation does not prove immunity to core dumps/swap, that sequential ledger hashes do not capture every concurrent race, and that tests should not be mistaken for a production review of parser edge cases. The workflow deliberately has **no Docker socket/secret mount**, uses read-only source/binary binds, and existing separate GitHub Experimental Security CI already performs `go test -race ./...`. These safeguards are separate, not a proof of all process memory confidentiality. Real HUB/Guardian test is limited to a sequential, ephemeral-loopback scenario. Additional concurrent stress, credential-lifecycle proof, signed policy mode, and separate human audit remain open.
